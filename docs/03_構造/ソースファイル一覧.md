# ソースファイル一覧 — equipment-lending

> 読者: 「このファイルは何をするものか」「触っていいのか」を知りたい実装者・AI エージェント
> 読むタイミング: 見覚えのないファイルに出くわした時・`scripts/` や `tools/` にファイルを足す前
> ⛔ 概要どまりにする。引数・入出力の項目・処理手順は書かない（各ファイルの先頭のコメントが正）。

## 対象範囲と数え方

- 対象: `scripts/` の `.ps1`・`.sql`・`.cjs`、`backend/` の Flyway の `.sql`（DB に副作用があるため）と `.java`。必要になった時に足す（JIT）。
- 対象外: `frontend/` の画面（置き場所は `ディレクトリ構成定義.md` の宣言どおり。Vite の既定構成で用途が分かるため）、`node_modules/`・`target/` の生成物、git 管理外のファイル。
- 作業用ソース（`tools/`）は今は無い。

## ⛔ 副作用のあるファイル

| パス | 何が起きるか | 安全に中身を見る方法 |
|---|---|---|
| `scripts/create_db.ps1` | PostgreSQL に DB とロールを作り、`backend/.env` を書く（既にあれば何もせず止まる） | 実行しない。テキストとして読む |
| `scripts/create_db.sql` | 同上（DB とロールを作る） | 実行しない。テキストとして読む |
| `scripts/check/*` | 接続先の DB に申請を足し、状態を進める（`api_checks.ps1` は申請 1 件を作って却下する）。`e2e_ai_check.cjs` はキーがあれば Dify のクレジットを 1 回使う | テキストとして読む。打つのはサーバーが `equipment_lending` を向いている時だけ |
| `backend/.../db/migration/V*.sql` | サーバーを起動すると接続先の DB にテーブル・初期データを作る。⛔ 一度流した V ファイルを書き換えない（Flyway の照合で起動が止まる。直す時は V3 以降を足す） | テキストとして読む。テストは H2 のメモリ上で流れる |
