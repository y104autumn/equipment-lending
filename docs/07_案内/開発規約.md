# 開発規約 — equipment-lending（今回の実施方法とルール）

> 読者: このリポで作業する人と AI エージェント
> 読むタイミング: 着手前・コミット前・Figma を操作する前
> 作業の順番の正は `docs/08_プロジェクト管理/WBS.md`。決めたことの正は `docs/01_意思決定/意思決定記録.md`。ここは「どうやるか」だけ。

## 1. ツールの役割と使い方

| ツール | 役割 | 使い方の正（リファレンス） | このリポでのルール |
|---|---|---|---|
| Claude Code | 設計書・コード・テストを作る中心 | 公式 `https://code.claude.com/docs` | 作業は WBS の行の順に行う。行が無い作業に着手しない |
| Figma（MCP） | 画面を設計する | 公式 `https://developers.figma.com/docs/figma-mcp-server/` | 下の §2 |
| sdlc-doc-templates | リポの骨格・設計書のひな形 | `00_リポジトリ雛形/README.md` §1・§2 | `git init` が先。`.template` をリポに入れない。`00_` のディレクトリを作らない |
| GitHub（`gh`） | リモートのリポジトリ | `gh repo --help` | このリポは public（意思決定記録 D-12）。認証情報・`.env` をコミットしない |

## 2. Figma（MCP）を使う時のルール

| ルール | WHY |
|---|---|
| 接続先はリモート版 `https://mcp.figma.com/mcp` | デスクトップ版は有料の席が要る |
| 認証（`/mcp` → figma → Authenticate →「Allow access」）はオーナーが行う。AI は認証情報を扱わない | 認証は人の操作に限る |
| 認証後、`claude mcp get figma` の Status が Connected になってから使う | 登録だけでは使えない |
| 読み取りのツールは月 20 回までしか使えない（無料プラン）。書き込み（`create_new_file`・`generate_figma_design`）と `whoami` は数えない。読み取りは「作った画面の確認」の 1〜2 回に絞る | 回数を使い切ると月内は読めなくなる |
| 作るのは要件定義書 §4 の 1 画面だけ。作ったら URL とキャプチャを `docs/05_振る舞い/画面設計書.md` に載せる | 「作れたことを確かめる」のが目的 |
| ボット確認で止まったらオーナーに伝え、AI は回避策を作らない | 確認を迂回しない |

## 3. コードのルール

| 項目 | 規約 | WHY |
|---|---|---|
| 置き場所 | サーバーは `backend/`、画面は `frontend/`（プロファイル D・型 b） | 意思決定記録 D-7 |
| 入力の検査 | 画面とサーバーの両方で行う。サーバーは 400（入力）・404（無い）・409（状態の表に無い操作）を返す | 画面を通らない呼び出しも止めるため（要件定義書 §5・§7） |
| 状態の遷移 | 状態の表（要件定義書 §3）をサーバーの 1 箇所に書き、そこ以外で遷移させない | 遷移の規則が散らばると表と食い違う |
| コメント | 設定値・依存の追加・自明でない実装には WHY を書く | WHY はコードに現れない |
| テスト | 正常系と異常系の両方。`mvn test` は `-q` を付けずに打ち、`Tests run:` 行で合否を見る | `-q` は結果の行を消すので、無出力が成功に見える |

## 4. コミットとブランチ

| 項目 | 規約 |
|---|---|
| 言語 | 日本語（プレフィックスのみ英語 `feat:`／`fix:`／`docs:`／`chore:`／`test:`） |
| 粒度 | 1 コミット＝1 つの意図。WBS の 1 行が終わるごとにコミットする |
| ブランチ | `main` のみ（1 人・当日中の模擬のため） |
| push | コミットしたら push し、`git log @{u}..HEAD` が 0 件であることを値で確かめる |

## 5. 確認の流れ

| 段 | 誰が | 何を |
|---|---|---|
| 1 | メイン（Claude Code） | 作る。ビルド・テストを自分で打って値で確かめる |
| 2 | レビュー用のサブエージェント（コード用・設計書用） | 読んで指摘する（書き換えない） |
| 3 | メイン | 指摘を直す |
| 4 | オーナー | 最終確認。問題があればメインが直す |
